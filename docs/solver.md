# Solver Engineering, DCFR & Equilibrium Strategy Artifacts

## 1. Solver Engine Overview

Pokeria’s solver engine (`apps/solver/`) is a high-performance native Rust implementation of **Discounted Counterfactual Regret Minimization (DCFR)** for No-Limit Texas Hold'em (NLHE). It is built upon and vendored from the open-source [`ucsandman/postflop`](https://github.com/ucsandman/postflop) project by **Wes Sander** under the [MIT License](../apps/solver/LICENSE) (see [`ADR-0004`](adr/ADR-0004-solver-upstream-patch-and-ev-export.md)).

It is designed to solve heads-up postflop spots across user-defined ranges, bet sizing trees, stack depths, and casino rake structures.

## 2. Mathematical Foundation: Discounted CFR (DCFR)

Located in `apps/solver/engine/src/cfr.rs`.

Standard Counterfactual Regret Minimization (CFR) can take many iterations to correct early suboptimal explorations. Pokeria uses DCFR, which applies parameter-controlled discounting to cumulative positive and negative regrets, as well as strategy accumulation.

### 2.1. Parameter Tuning
Pokeria adopts the empirically proven DCFR discounting configuration:
* $\alpha = 1.5$: Discount exponent for positive cumulative regret.
* $\beta = 0.0$: Discount exponent for negative cumulative regret (instantly clears deep negative regrets).
* $\gamma = 2.0$: Discount exponent for strategy weighting (places heavier emphasis on later, higher-quality iterations).

At iteration $t$:
$$R^+(a) \leftarrow R^+(a) \cdot \frac{t^\alpha}{t^\alpha + 1}$$
$$R^-(a) \leftarrow R^-(a) \cdot \frac{t^\beta}{t^\beta + 1}$$
$$S_t(a) \leftarrow S_{t-1}(a) + \sigma_t(a) \cdot \left(\frac{t}{t + 1}\right)^\gamma$$

### 2.2. Regret Matching+ (RM+)
Next-iteration action probabilities are generated by normalizing positive cumulative regrets:
$$R^+(a) = \max(0, R(a))$$
$$\sigma_{t+1}(a) = \begin{cases} \frac{R^+(a)}{\sum_{a'} R^+(a')} & \text{if } \sum_{a'} R^+(a') > 0 \\ \frac{1}{|A|} & \text{otherwise (uniform distribution)} \end{cases}$$

## 3. Game-Tree Modeling & Node Locking

Located in `apps/solver/engine/src/tree.rs`.

### 3.1. Extensive-Form Tree Representation
A spot is constructed into an extensive-form game tree based on:
1. **Board cards**: Flop (3 cards) or Turn (4 cards).
2. **Ranges**: 13x13 preflop range matrix expanded into specific card combos (up to 1,326 combos minus card removal).
3. **Starting Financials**: Starting pot and effective stack depth.
4. **Bet Sizings**: Sizing percentages per street for Out-of-Position (OOP) and In-Position (IP) players.

### 3.2. Node Locking Support
Pokeria supports freezing specific decision nodes to study exploitative responses against stubborn or leaky opponents. Locks are configured via TOML arrays:
```toml
[[locks]]
line = "check,bet:50"   # Path from root to target decision node
player = 1             # 0 = OOP, 1 = IP
freqs = [0.70, 0.30]   # Frozen frequencies across actions
```
During DCFR execution, locked nodes retain their designated frequencies; regret accumulation is paused on locked nodes while the counterparty solves for the optimal exploitative counter-strategy.

## 4. Casino Rake & Non-Zero-Sum Unilateral Best Response

Located in `apps/solver/engine/src/nlhe.rs`.

Standard zero-sum poker solvers define exploitability as:
$$\text{Exploitability} = \frac{\text{BR}_0 + \text{BR}_1}{2}$$
In raked games, this equation produces mathematical errors (including negative exploitability) because chips extracted by rake make $\sum U_i < 0$.

Pokeria evaluates unilateral best-response gains independently:
$$\Delta_0 = \max_{\sigma_0'} u_0(\sigma_0', \sigma_1) - u_0(\sigma_0, \sigma_1)$$
$$\Delta_1 = \max_{\sigma_1'} u_1(\sigma_0, \sigma_1') - u_1(\sigma_0, \sigma_1)$$
$$\text{NashConv} = \Delta_0 + \Delta_1$$

### Stopping Conditions & Thresholds
A solve is stopped when either condition is met:
1. **Target Exploitability**:
   $$\text{Exploitability} \le 0.5\% \text{ of pot} \quad (\text{or } 0.1 \text{ chips in small pots})$$
2. **Iteration Cap**: Iteration count reaches configured limit (default: 2,000 - 5,000 iterations).

## 5. Artifact Storage & Byte-Offset Node Indexing

Located in `data/solutions/` and `apps/api/app/domain/poker/node_extractor.py`.

### 5.1. Solution Manifest Catalog
All precomputed solutions are indexed in `data/solutions/manifest.json`. Each entry defines:
- Canonical scenario key and board.
- Starting pot and effective stack.
- SHA-256 artifact checksum.
- Measured exploitability (chips and % of pot).
- Root action EVs (both zero-sum and raked pot shares).
- Engine version and git commit fingerprint.

### 5.2. Byte-Offset Seeking (`NodeMapIndexer`)
Postflop turn and river trees can exceed 200MB and contain over 130,000 decision nodes. Loading an entire JSON tree into memory on every user decision would cause 200-500ms API latency.

Pokeria utilizes a precomputed byte-offset index (`.idx` / binary seek table):
- Every decision node's byte offset within the solution file is indexed at build time.
- During interactive training drills, `NodeMapIndexer` performs an $O(1)$ random seek to read only the targeted node.
- **Benchmarked Retrieval Latencies**:
  - Root node: 25-35 ms
  - Turn node (50% depth): 65-90 ms
  - Deep River leaf node: 120-155 ms

## 6. Decision Grading Authority & UNGRADED Verdicts

Located in `apps/api/app/domain/training/grading.py`.

Pokeria acts as a server-authoritative grading authority. To protect pedagogical integrity, it never invents EV numbers when data is absent or corrupted.

### 6.1. Cash Decision Regret Formula
$$\Delta \text{EV} = \max_a \text{EV}(a) - \text{EV}(a_{\text{chosen}})$$
* **Strong**: $\Delta \text{EV} \le 0.10$ chips.
* **Acceptable**: $\Delta \text{EV} \le 0.50$ chips (or mixed frequency $\ge 20\%$).
* **Inaccuracy**: $\Delta \text{EV} \le 1.50$ chips.
* **Mistake**: $\Delta \text{EV} \le 4.00$ chips.
* **Blunder**: $\Delta \text{EV} > 4.00$ chips.

### 6.2. When Pokeria Returns UNGRADED
A decision is assigned `GradeCategory.UNGRADED` in the following documented scenarios:

| Grading Provenance | Condition | Explanation |
| :--- | :--- | :--- |
| `UNVALIDATED_SOLVER_RUN` | Solution failed convergence check | Exploitability $> 1.0\%$ of pot; solver did not reach Nash equilibrium. |
| `CSTE_POLICY_PENDING` | Tournament ICM decision | Raw tournament equity cannot be mapped to arbitrary chip-EV thresholds. |
| `ILLEGAL_ACTION` | Action not in strategy tree | Player took an illegal action or an action not modeled in the bet tree. |
| `FREQUENCY_ONLY` | Missing action conditional EV | Reference provides frequencies but lacks conditional EV values; never fabricates 0.0 EV loss. |
| `CORRUPTED_ACTION_EV` | `NaN` or `Inf` in reference data | Floating-point anomaly in solution file; rejected immediately. |

## 7. Educational Ranges vs. Exact GTO

Pokeria provides preflop range charts for opening, 3-betting, and defense. It is vital to understand why educational ranges are not always identical to raw solver outputs:

1. **Human Simplification**: Raw GTO solutions frequently feature mixed strategies across 80% of hands (e.g., raise A5s 23.4% of the time, fold 76.6%). Educational charts round these into clean, actionable heuristics (pure raises or clean 50/50 splits) to build repeatable intuition.
2. **Rake Realities**: Solver solutions change drastically between 0% rake (high-stakes/tournament) and 5% with high caps (micro-stakes). Educational charts clearly state their intended rake environment.
3. **No False GTO Guarantees**: Pokeria labels human-curated charts as `ILLUSTRATIVE_PRACTICE_CHART` and reserves `GTO_SOLVER_EQUILIBRIUM` strictly for fully converged native solver trees.
